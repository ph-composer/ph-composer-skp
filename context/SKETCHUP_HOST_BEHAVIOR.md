# SketchUp host behavior: measured facts for agents

**DATE:** 2026-09-30

Unless a row says otherwise, every fact here was measured in the predecessor, PH-Navigator for
SketchUp, on SketchUp Pro 2026.1 build 26.1.188 (macOS, embedded Ruby 3.2.2) between 2026-09-06 and
2026-09-17, through its development host bridge. Rows marked "Measured in PH-Composer" come from this
repository's own bridge on the same host. designPH 2.2.29 was installed and loaded on that host throughout.
Re-measuring the observer-ordering facts on a host without designPH is a pending gate for this
project; until then treat them as likely and pin them in the stub as the predecessor did.

Each fact names the code that depended on it and the offline test or stub rule that pinned it in
the predecessor. Tests for facts this repository already depends on were ported and are named
in the Pinned by column; tests named for Volumes, Spaces and `GeometryReference` are the
predecessor's and move here with the Spaces feature. When a fact changes on a newer
host, update the stub and this file in the same change. The full record, including the designPH
and Dynamic Components facts this file drops, is
[`../../../ph-navigator-sketchup/context/SKETCHUP_HOST_BEHAVIOR.md`](../../../ph-navigator-sketchup/context/SKETCHUP_HOST_BEHAVIOR.md).

## Observers and edit contexts

| Fact | Consequence | Pinned by |
| --- | --- | --- |
| Observer callbacks for one user action arrive after the Ruby call that caused them returns, and in a fixed order: `onTransactionCommit`, then `onActivePathChanged`. On leaving a Volume with Escape (or `Model#close_active`), the commit callback arrives with `active_path` already outside the Volume. | A reconciler that rebaselines on commit loses the Volume it needs to protect. Either callback must queue the exit protection from the baseline. | `test_exit_protects_when_commit_arrives_before_path_change` |
| For an operation Ruby opens and commits itself, `Model#commit_operation` delivers `onTransactionCommit` synchronously, before the call returns. Measured in PH-Composer on 26.1.188, 2026-09-18. | The session recognizes its own commit inside the operation; it still handles a callback that arrives later. | Stub `Model#commit_operation`; `tests/sessions_test.rb` |
| `Model#abort_operation` fires `onTransactionUndo`, synchronously, and no `onTransactionAbort`. Measured in PH-Composer on 26.1.188, 2026-09-18. | An observer cannot tell an aborted operation from a user Undo by the callback alone. The session ignores the Undo callback inside its own operation, so a rolled-back change leaves the revision. | Stub `Model#abort_operation`; `test_abort_reports_an_undo_as_the_host_does` |
| A native copy of a Group (Option Move/Copy, Paste, Paste in Place, an array) delivers `onTransactionCommit` first and `onElementAdded` for each new Group after it; the Group already carries its instance dictionaries in that callback. The original keeps its persistent id and transformation; the copy has a new persistent id. Measured in PH-Composer on 26.1.188, 2026-10-12. | A watcher triggered only by commit misses the copy: schedule deferred work from the addition too, and treat the occurrence already in the baseline as the original. | [P2 spike](../planning/archive/copied-zone-edit-refusal/evidence/p2-host-spike.md); `ContainerWatch#added` |
| Aborting a transparent operation that joined a native gesture undoes the gesture as well: after a Paste in Place, `abort_operation` on the follow-up fired `onTransactionUndo` and the pasted Group was gone. Committing after a failure keeps whatever the follow-up had written. Measured in PH-Composer on 26.1.188, 2026-10-12. | Automatic follow-up work must never abort and must not commit a partial write: capture what it may change, write that back on failure, then commit. | [P2 spike](../planning/archive/copied-zone-edit-refusal/evidence/p2-host-spike.md), S4 |
| Typing an array count (`5x`) after a Move/Copy makes SketchUp undo the first copy (`onTransactionUndo`, taking any transparent follow-up joined to it) and commit all copies as one new transaction. Measured in PH-Composer on 26.1.188, 2026-10-12. | A follow-up that ran on the first copy is undone with it; rebaseline on Undo and handle the N copies of the final transaction as one batch. | [P2 spike](../planning/archive/copied-zone-edit-refusal/evidence/p2-host-spike.md), S9 |
| Leaving or entering a group edit context is itself a transaction: `onTransactionCommit` fires on Escape, and a context change marks the Model modified. | Do not read a commit as "geometry changed"; a save followed by a context close leaves the title marked modified. | Recorded; no stub rule |
| Inside `onPreSaveModel`, `Model#active_path` is empty although the edit context is still open on screen. SketchUp restores the context after the save, but not a context with a locked Group on its path: locking the open Volume inside `onPreSaveModel` left the Model at the root, with no path-change callback. Measured again in PH-Composer on 26.1.188, 2026-10-16 (D3a-19 spike). | Pre-save work cannot read the Volume from the path; the reconciler uses its baseline Volume. | Stub `Model#save` (`fire_pre_save`) |
| Setting `Model#active_path` inside `onPreSaveModel` makes SketchUp serialize the reopened context in world coordinates: the reopened file has the Space transform baked into its Volumes. In memory nothing has moved. | Never change the path during pre-save, and do not lock a Group on the open path there either, or the user is left at the root. | Stub `Model#save` raises on a pre-save path change |
| `onSaveModel` fires after the file is written, on the restored path. `modified?` is then false after a save at the root and true after one inside an edit context, which also leaves a "Close" entry on the Undo stack; undoing that entry changes nothing visible. Measured in PH-Composer on 26.1.188, 2026-10-16. | A save inside a group always leaves the title marked modified; that is the host's, not the extension's. | Stub `Model#save` fires it and sets `modified?` from the path |
| An autosave fires `onPreSaveModel` and `onSaveModel` exactly as a save does, with `Model#path` still the Model's own file, and writes its copy to SketchUp's `working` folder (`~/Library/Application Support/SketchUp 2026/SketchUp/working/` on macOS). It fired about a minute after a change pending from Ruby, with SketchUp in front. Measured in PH-Composer on 26.1.188, 2026-10-16, with the autosave interval set to 1 minute. | An extension cannot tell an autosave from a save, so whatever a save does to the user happens every few minutes. | Recorded; no stub rule |
| While a context is open, the API reports `Group#transformation` of entities on the active path in world coordinates, not relative to their parent. Closing the context restores relative values. Measured again in PH-Composer on 26.1.188, 2026-10-15: with a Space Group open, the Space itself reported identity and each of its child Volumes reported its transform composed with `model.edit_transform`; with one Volume open inside it, the Space and the open Volume reported identity and the sibling Volume reported its world transform. Closed again, all read relative to their parents. | Compare against stored home transforms only through a path-aware transform reader; a raw comparison reports `volume_moved` for every open Volume, and a Volume created inside an open Space stores a world transform as its home. Only a child of the innermost open Group converts (through `edit_transform`); a child of an outer Group on the path is not compared. | `Spaces::Protection.local_transform`; `test_a_child_of_the_open_context_reads_and_writes_relative_to_its_parent` |
| Opening a repeated parent context rebases shared child transformations, and `Sketchup::InstancePath#transformation` can then return a wrong position for another occurrence of that parent. | Withhold world geometry for shared definitions while their edit context is open, or compensate with the current raw root-to-leaf transform. | Predecessor window reader phases 3a and 3b1 |
| After `Model#active_path=` opens a Volume inside a Space that sits in a rotated plain group, `View#zoom(face)` frames that face correctly. A screen box computed from `edit_transform` times the entity's reported bounds disagreed with the capture. | Zoom the target entity directly; judge framing from a capture, not from coordinates computed inside an open context. | Predecessor Spaces table controls, phase 4 |
| `Selection#add` of an entity outside `Model#active_entities` does nothing and raises nothing. | Selecting a sibling Volume from inside another Volume needs the context closed first. | Stub `Selection#add` ignores out-of-context entities |
| On a Model that is not the active document, `Model#active_path=` with `nil` or `[]` and `Model#close_active` leave the edit context as it was (`close_active` answers false), while a non-empty path, deeper or shallower, is honored. Measured on 26.1.188, 2026-10-18, with two documents open ([C16 run](../planning/archive/phase-03a1/evidence/p3a1-16-integrated-acceptance.md)). | A return to the root on a Model SketchUp is not showing cannot happen; refuse it before any boundary writes (`EditContext.enter`, `session.inactive`). | No stub rule: `EditContext.enter` refuses before assigning; `tests/context_navigation_test.rb` |
| `Model#active_path=` from Ruby is honored outside save callbacks and fires `onActivePathChanged` later, not synchronously. | Read state in a later call; a `sleep` in the same call blocks the UI timers that deliver callbacks and run deferred work. | Bridge usage rule |
| The Undo stack carries the context changes as entries of their own: entering a Group natively is "Open", leaving it by Escape or by a Select-tool click outside it is "Close", and a Ruby `Model#active_path=` that leaves a context is also recorded, as "Open", and clears Redo. Undoing a "Close" reopens the context; a transparent protection joined to the close is undone with it, and Redo stays available. Measured in PH-Composer on 26.1.188, 2026-10-16 (P3a-12). | Count a gesture's Undo steps from the Edit menu label, and do not read an extra "Open" or "Close" as automatic work.
