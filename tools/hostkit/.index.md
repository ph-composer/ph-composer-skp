# The host kit: driving SketchUp from a terminal

Development tools, never shipped. `tools/rbz/build.py` refuses any `hostkit` path in the RBZ.

| File | What it does |
| --- | --- |
| `host_bridge.rb` | In-process server. `make bridge-install` copies it into the SketchUp Plugins folder, where it listens on loopback with a random token, evaluates Ruby on the main thread and tees the Ruby Console into `ph_composer_host_bridge.console.log` beside its state file. Both files are owner-only (mode 0600); run `make bridge-uninstall` on the machine before a release build (the checklist in `docs/DEVELOPMENT.md`) |
| `host_bridge.py` | Client and lifecycle tool: `launch`, `wait`, `ping`, `eval`, `state`, `save`, `shot`, `key`, `console`, `show-model`, `wait-for`, `diagnostics`, `fault`, `quit` |
| `diagnostic_reader.rb` | Loaded with the helpers. `PhComposerHost.diagnostics(filters)` reads the log's own projection (`Diagnostics.tail_window`) through `Diagnostics.sanitized`, filtered by session, incident, run and least severity, paged by a cursor that names its process and the next line to read (or the `newest` matches); reports eviction, a restarted process, the log's health and schema, and the build. Never file bytes or the logger's state |
| `host_diagnostics.py` | The client half: `host_bridge.py diagnostics` and `wait-for --diagnostics`, filters checked against the extension's exact forms before the call |
| `fault_controls.rb` | Loaded only by `host_bridge.py fault`. `PhComposerFaults` arms, observes and restores the named development faults `lost_reply`, `silent_runtime` and `failed_write` on a synthetic fixture, with a checked baseline, a bounded record of what each intercepted and a restore read back against the baseline. Loading arms nothing |
| `host_faults.py` | The client half: `host_bridge.py fault arm|observe|restore <fault>`, targets checked before the call; a failed arm or restore exits 1 |
| `host_wait.py` | The bounded wait behind `wait-for`: a named read-only condition polled in separate bridge calls under one monotonic deadline, ending in one versioned JSON result (`met`, `timed_out`, `cancelled`, `invalid_condition`, `session_missing`, `session_switched`, `target_missing`, `read_failed`, `bridge_unavailable`) with the last observed state |
| `host_helpers.rb` | Loaded by `launch`. `PhComposerHost.state` reports SketchUp and Ruby versions, the loaded extension's identity and features, and the Model by file name only; `shot` writes a viewport image |
| `acceptance_ledger.py` | Read-only source snapshots, affected-case screening and validation/append of explicitly observed acceptance summaries; no automatic host execution |
| `acceptance_case.py` | One native case in two commands: `begin` reads the host identity from the bridge, checks the installed extension, captures the baseline and starts the case's `steps.md`; `finish` attaches the observations and appends the ledger row; [procedure](ACCEPTANCE_RUN.md#one-case-in-two-commands) |
| `acceptance_run.py` | Immutable private baselines, preflight observations, assertion dependency screens, observation receipts, installed-package comparison and local link checks; [procedure](ACCEPTANCE_RUN.md) |
| `runtime_probe.rb` | Loaded by hand. `PhComposerRuntimeProbe` opens the runtime page for the active Model, sends two probes at once, reports results against the manifest's gates, and tears down or cancels with a report of what it released; `panel_ready` times a fresh panel open |

```sh
make bridge-install
make install                        # the RBZ's loader and folder into the Plugins folder
uv run tools/hostkit/host_bridge.py launch _private/<model>.skp --fresh-from _private/<blank>.skp
uv run tools/hostkit/host_bridge.py state
uv run tools/hostkit/host_bridge.py console --tail 40
uv run tools/hostkit/host_bridge.py quit
```

`launch` quits any running SketchUp first. `quit` closes every open document without saving it,
so unsaved work in an open document is lost. Check before launching on a machine where someone is
working.

Rules that keep runs honest:

- Read state in a call of its own after an action. Deferred work runs on UI timers, which cannot
  fire while an `eval` blocks the main thread; a `sleep` inside the eval proves nothing.
- `save` and `quit` send Escape through System Events when the Purge Unused prompt appears. Keys
  go to `process "SketchUp"` only.
- The bridge is loopback only and token guarded. Remove it with `make bridge-uninstall`.

The runtime probe, one eval per step so the runtime page and its timers run in between:

```sh
uv run tools/hostkit/host_bridge.py eval 'load "<repo>/tools/hostkit/runtime_probe.rb"'
uv run tools/hostkit/host_bridge.py eval 'PhComposerRuntimeProbe.start'          # its "session" and "run"
uv run tools/hostkit/host_bridge.py wait-for runtime_probe_finished --param session=<session> \
  --param probe_run=<run> --deadline 120                                          # polls status
uv run tools/hostkit/host_bridge.py eval 'PhComposerRuntimeProbe.teardown'   # "released" must be true
```

Switching the shown Model, which fires `onActivateModel`. **It brings SketchUp to the front**, so tell Ed
in one line before running it:

```sh
uv run tools/hostkit/host_bridge.py show-model b07 --deadline 15   # exits 0 only when shown and restored
```

It reads the frontmost process, AXRaises the one SketchUp document window whose title (its name before
` - SketchUp`) contains the text, waits until `Sketchup.active_model.title` contains it, ignoring case on both
sides, then fronts the previous process again by its System Events name and reads that back. It prints JSON:
`ending` (`shown`, `refused`, `raise_failed`, `timed_out`, `read_failed`, `bridge_unavailable`, `cancelled`),
`window`, `before` and `shown` (the active Model's title before and after), `previous`, `restored` and
`error`. It refuses, without fronting SketchUp, when no window or more than one matches, the bridge is not
answering, or the frontmost process cannot be read; once a raise is attempted, focus is handed back on every
path, an interrupt included. `--deadline` (at most 120 s) bounds the wait for the switch only, and a reply
that arrives after it is `timed_out`. Exit status is 0 only when shown and
restored, 2 when the bridge is unavailable. A Model that was already active ends `shown` at once, with
`before` already containing the text: there was no switch, so no `onActivateModel` fired. The text reaches AppleScript as an argument, never in its source.

Waiting for a host condition, rather than sleeping or polling by hand:

```sh
uv run tools/hostkit/host_bridge.py wait-for session_settled --param session=<uuid> --deadline 30 --json
uv run tools/hostkit/host_bridge.py wait-for revision_changed --param session=<uuid> --param revision=4
uv run tools/hostkit/host_bridge.py wait-for export_finished --param session=<uuid> --param caller=<handle> \
  --param task=<export_id>
```

Reading the extension's log, filtered and paged, rather than tailing the file:

```sh
uv run tools/hostkit/host_bridge.py diagnostics --session <uuid> --severity warning --json
uv run tools/hostkit/host_bridge.py diagnostics --cursor <next_cursor from the last read>
uv run tools/hostkit/host_bridge.py diagnostics --run-id <export task id> --newest   # the latest records
uv run tools/hostkit/host_bridge.py wait-for session_settled --param session=<uuid> --diagnostics --json
```

A read returns at most 100 records (128 KiB), each reduced to the fields and values the log accepts, with
`cursor_state` `start`, `continued`, `evicted` (and how many lines were lost) or `process_restarted`, so it
never implies a complete history. It covers this process's 256 KiB tail only; earlier history is in the log
file the support report reads. A log schema the reader does not know is refused. Installed-byte proof stays
with the acceptance package comparison. `--diagnostics` adds the session's recent warnings and errors beside a
wait's ending (an export wait's run, else its session), read within what is left of its deadline and never
after a cancel, and never changes it; a wait that timed out has no budget left, so read `diagnostics` after it.

Reproducing a failure with a named development fault, arm, observe and restore as separate calls, chained so
a failed step stops the case:

```sh
uv run tools/hostkit/host_bridge.py fault arm silent_runtime --session <uuid> --drop runtime.ready --json &&
  # ... start the work, wait-for its ending, read its diagnostics ...
  uv run tools/hostkit/host_bridge.py fault observe silent_runtime --json &&
  uv run tools/hostkit/host_bridge.py fault restore silent_runtime --json
```

A fault arms only on a Model under `_private/host/` or a temporary folder (never a client Model elsewhere in `_private/`), and only on a clean baseline
(`silent_runtime` refuses while a runtime is live for the session). `restore` reads the target back:
`restored` is false, and the command exits 1, when a runtime is still running or holds a resource, a stored
preference differs from its baseline, or the panel's open state changed. A failed restore keeps the original
baseline: the fault stays `restore_failed`, cannot be re-armed, and passes a later restore only once the
target reads back as that baseline. `armed` says whether it intercepts now and `pending_restore` whether a
restore is still owed. A restore in a process that never armed the fault (SketchUp restarted) cannot read
anything back and is not certified; a preference the host cannot read back is never a baseline or a match.
The client refuses a process holding another revision of the controls (`load` runs once per process): restart
SketchUp after changing them. `failed_write` refuses writes only while its synthetic Model is the active
one, since preferences are machine-wide. `interceptions` counts every hit; the hit log keeps the first 20 and
says how many it left out. The interceptor stays in the process, inert, after restore, so finish with a fresh process
on the normal installed build. Product behavior under a fault is asserted by the production cases; these
controls only make the fault repeatable.

Each condition names its session (and its task or probe run) by id and never follows another Model: a closed session
ends `session_missing` and another active Model ends `session_switched`. Parameters must be in the exact
form the extension generates, so nothing else reaches the Ruby read. Every poll is one eval that must finish,
connection to last byte, within the remaining budget, so timers run between polls and no call outlives the
deadline; an answer that arrives after it is `timed_out`, not `met`. Exit status
is 0 only when the condition was met, 2 when the bridge is unavailable; a malformed state file or reply counts
as unavailable. The deadline (at most 3600 s) and interval (at most 60 s) must be positive. A wait applies, retries and cancels
nothing; `timed_out` describes the observation, not the work. A projection without the session's shape (or
the condition's) is `read_failed`, never `met`; a probe stopped before its results is `target_missing`. Two
effects belong to the export tasks, not the wait: the first read of a session builds its empty task list, and
`owned_by` prunes finished tasks past their retention, as any status poll by the task's owner does.

The predecessor's export and storage probe commands stay behind until their owning stages. Spaces
host checks run the panel-closed walkthroughs in
[`tools/examples/authoring/`](../examples/authoring/README.md) through `eval`, and an external client
reaches the same operations over the Agent Access endpoint
([`agent_access_probe.py`](agent_access_probe.py)). The host facts these tools rely on are in
[`context/SKETCHUP_HOST_BEHAVIOR.md`](../../context/SKETCHUP_HOST_BEHAVIOR.md).
