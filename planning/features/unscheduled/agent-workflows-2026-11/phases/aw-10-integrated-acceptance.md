# AW-10 · All-feature acceptance and handoff

STATUS: Authorized 2026-11-10, not started. ISSUE: https://github.com/ph-composer/ph-composer-skp/issues/439 (implementation); #435 tracked the review/planning publication.
DEPENDS ON: AW-01 through AW-09 selected scope. ACCEPTANCE: entire selected register, especially A17.

## Outcome

Exact recorded clients prove the user's complete inspect/build/edit/QA loop on the installed app,
with no development eval, private repository knowledge or fixture-preselected targets in the client work.

## Scenarios

1. Fresh connection, panel closed, empty selection, two open Models sharing a file name. Discover
   guide/capabilities, verify the intended context and refuse the other token scope.
2. Enumerate existing synthetic floor/shell geometry; create Zone and Space records, classify Faces,
   solve adjacency, set Building-Segment/Level and update Space/Volume/Floor values. Report exactly
   what each action accepted. Exercise safe copied/locked/legacy conflicts and approved repairs.
3. Create/read/edit Materials and a layered Assembly; copy/assign a library Material atomically;
   assign the Assembly to Faces and confirm counterpart orientation.
4. Create Window products and a large Type; inspect elements/topology; derive a placement from a host
   extent with holes, place/rename/change/repair Units and read back geometry and metadata.
5. Discover unselected Edges, create a Thermal Bridge Type, assign/read/clear by refs; inspect a long
   run and more than one page of invalid/orphan findings. Apply the selected safe repair and verify.
6. Retrieve all QA for an oversized model; deliberately blocked export yields complete original-run
   diagnostics after a user edit. Fix selected issues, export, read canonical HBJSON and report,
   verify hashes and actual object/reference values. Exercise exact-revision start if selected.
7. Inject a lost reply, repeated key, stale revision, revocation, model activation/close and supported
   gesture conflict. Demonstrate no duplicate mutation or silent overwrite and truthful outcomes.
8. Capture/locate/Colour-by and chosen artifact/history slices; explicitly state what is not in an
   image. A local-path-only client recipe must name that prerequisite.

## Evidence

Use existing synthetic fixtures and walkthroughs; broaden them at the missing boundary rather than
create a second test framework. Record source commit/build/manifest, API minor, host/OS/client
versions, fixture identity, grants, calls/results and verification. Native fixture preparation is
separate from client actions. Keep tokens, user paths, client data and licensed content out of receipts.

Run the full offline gate once the implementation is coherent; record affected focused results and
native Undo/Redo/save/reopen. Use one final consistency review with the architecture rubric and
deterministic results, not another equivalent panel. Address all in-scope findings; mark unsupported
and unselected cases explicitly rather than calling them passed.
