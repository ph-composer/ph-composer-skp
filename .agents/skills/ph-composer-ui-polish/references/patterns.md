# Current PH-Composer UI reference points

These paths identify accepted patterns. Reinspect them before reuse and extract shared components when the behavior truly matches.

Paths under **Local** are in this repository at `src/ph_composer/html/`. The UI kit registers modules with `PhComposerUI.define` and uses the `phc-` class prefix. Paths under **Predecessor only** are in `../../ph-navigator-sketchup/src/ph_navigator_sketchup/html/` and have not transplanted; they are reference points for screens this repository will build, not current files. The predecessor's Window Schedule, assigned-window propagation and designPH review screens do not transplant; their designPH-specific patterns are omitted here.

## Shared primitives (local)

- Drawing dimensions (`drawing_dimensions.js`, `drawing_dimensions.css`, exposed by `workspace.js`):
  `ui.dimensionRule` supplies the light rule, boundary dots and short extensions;
  `ui.dimensionValue` supplies matching HTML/SVG values and SVG click/Enter/Space activation.
  Assemblies and Window Types share these parts; owners retain unit formatting, guarded UnitFields
  and resize operations. `ui.inlineDimension` swaps an HTML value for an owner-supplied UnitField
  in place, preserving owner parsing, draft guards and Model writes. Drawing Bubbles use `detachedTrigger: true`, with their root outside the
  drawing scrollport and transformed ancestors. Keep labels in place and center them with layout,
  not transforms that relocate fixed editors. Check actual popup bounds and pointer access as well
  as Model readback; an offscreen input can still pass a programmatic fill check.

- Choice chips (`base.css`, `table.css`): selects use the shared inset chevron with reserved text
  space. Dark Assembly chips switch the chevron to light along with their label. Read-only table
  chips fill the column like editable ones and share their height, with a quiet hatch and lock
  instead of a chevron; their tooltip identifies them as read only. Accepted by Ed
  on 2026-10-05.

- App tooltips (`dom.js`, `overlay.js`): use `ui.tooltip(node, text)` to set or clear a hint and retain
  `aria-label` for the control's name. Do not set a native `title` attribute or an SVG `title` child:
  browser tooltips cover the styled hint after a long hover. The panel owns one shared hover/focus
  tooltip above bubbles, moving it inside an open native dialog when necessary. It preserves existing
  accessible descriptions and withdraws tips when their owner is hidden, removed or repainted with
  changed text. Standalone tables can attach the same layer. Accepted by Ed on 2026-10-05.

- `workspace.js` is the `ui` facade over the shared layer; each part has one file: `dom.js` (elements, `svg`, `commandButton`, `memoPaint`), `icons.js` (the icon registry, which throws on an unknown name, icon buttons and state-aware icon painting), `overlay.js` (`Bubble`, `ActionMenu`, dialog action rows, `formDialog`, `floatingNotice`, tooltips), `table.js` (table presentation) and `view_controls.js` (filter, group and order controls, group headings; an optional `guard`/`refused` pair refuses a filter edit while a draft would be hidden).
- `page_header.js` `ui.pageHeader({ title, actions, primary })`: the one page header. Title, secondary actions, then the one filled primary action at the right, with no caption and no count: a record count lives in the control row, where it can say how many a filter leaves. Every pane opens with it; a screen never styles its own heading. `--page-gutter` in `base.css` is the one horizontal inset: the pane carries it, and a rule that separates page regions (the subtabs row) runs through it to the panel edge. `setTitle` renames it in place. A detached session that covers a work surface (the Window Type Installs editor) uses the same header, with Cancel as its action and Save as its primary, so both stay in view.
- `subtabs.js`: `refused(reason, nextId)` names the tab that was asked for and `reselected(id)` reports a click on the shown tab. An owner whose surface is covered by a session (Installs) uses both to leave that session the way its Cancel does: at once when nothing is staged, through the discard confirmation otherwise.
- Installs drawing (`features/windows/install_editor.js`): edge state is data in the selection teal, solid when assigned and dashed when it follows the Model default; missing is the warning ink; `--drawing-highlight-halo` marks hover and focus. Each edge has a wide transparent target under a thin stroke. A perimeter value is written outside its element, a shared edge carries one "0", and a value is dropped where its edge is too short. Escape unwinds the form, then the copy list, then the session, from wherever focus is.
- Window Types frame (`features/windows/placement.js`, `editor.js`, `windows.css`): the Place tool's one setting, its anchor, is an icon beside Place that opens the nine anchors as a three by three grid of setting choices; the placement row shows only while the tool is placing. Rail rows give their whole width to the name and lay their action icons over the row end on hover and focus. An Empty element carries a small "Empty" caption.
- Library sidebar (`library/sidebar.js`, `library/rows.js`, `library/library.css`): a title that folds the sidebar, small muted group captions with a rule, and borderless record rows that tint on hover. All three are buttons; none is drawn as one. Beside the table of the same records (`besideTable`), "In this file" shows one line pointing at the source select in place of a repeated list. A library's row ends in a plus glyph and says "Add <name> to this file"; the record's card stays the place where the copy is reviewed and committed. Group headings carry their count; a list of more than 20 records starts with its groups folded, a search opens what it finds, and a fold the user chose stays. The rail sits at the right in both Builders, because the Window Builder's left edge holds its Types rail. Before any library exists, the sidebar's setup button reads "Add a library…". Under the search, two choice pills narrow the list: one category or all, and name order A to Z or Z to A; both are view state and survive a repaint.
- Library setup (`library/setup.js`): leads with the first task. With no library yet, the two ways to add one (file, folder) show at once as choice cards, each one native picker; afterwards they wait behind "Add a library…". An added library is named in a success line and marked in the list, and Done becomes the primary. Every change applies at once, so the footer is Done, never Cancel. Agent access (approved locations) is a folded `details` beneath, saying that adding a library needs no approval.
- Record forms (`record_form.js`): `RecordForm.required(label, control)` marks a field the form waits for. A disabled Create says why in the form's status line, in the muted hint tone, not the error red. New Assembly has no form: it creates "Assembly N" and opens the Builder with the title selected (`features/assemblies/form.js`, `section.js`). A record that is only numbers duplicates through `inventory_forms.js` `DuplicateForm` (a free "(copy)" name, selected, and Copy datasheet links), shared by Materials and Thermal Bridge Types.
- Export readiness (`sections/export.js`): one status line ("Ready to export." or "Finish N things before exporting."), then findings grouped by cause under "Before exporting" and "Worth checking". A group shows its sentence once with the record id taken out, a count, one Locate for every record in it, and "Open <tab>" from `panel.tabFor`, which features feed with `panel.workedOn(prefix, tab)`. Record ids stay in the row's tooltip.
- Empty and unfinished: an inventory with no records names the next step ("No Assembly records yet. Choose + New Assembly."), and keeps "match this view" for a filter miss. Window Types with no Types shows one prompt and no product libraries. "Not finished" is the amber alert glyph with what is missing in its tooltip, on a row where the gap belongs (the Window Types rail, the Zone tree's cells, an Assembly's withheld U-value).
- Pane regions (`panel.js`): `main` is the work surface; `inspector` is one column beside it showing a single section, chosen by tier (`tool`, `selection`, `record`, `ambient`) among those whose `when(state)` is true, with `"hold"` keeping a section that carries a draft, and away when none is; a pane whose work surface must not change width keeps an always-wanted `ambient` hint last (`order: 1000`) so the column always stands, or has no inspector at all and carries its selection's controls in the floating selection bar (`selection_bar.js`), as Zones / Faces does; `tools` are view controls the work surface places at the end of its control row with `panel.region(pane, "tools")`; `actions` are authoring tools (they change the Model) the page header places in its toolbar with `panel.region(pane, "actions")`. A shared `.phc-toolbar` groups related header tools under one outline. A tool that opens an inspector section is an icon toggle with a stable name, pressed while its section shows, built once and repainted so a press keeps its focus. Under 900 wide the inspector drops beneath the work surface. The work surface never moves down for either.
- `panel.js` owns the snapshot reducer, the one floating notice and the tabs. `panel.notify(message, tone, action)` raises a page-side notice, optionally with one text action that is its way out; `panel.navigationGuard(name, guard)` lets a section refuse a tab change while it owns work in progress; `panel.navigate(tab, intent)` opens another tab through those guards and hands `intent` to that pane's `onNavigate` sections. `request.js` gives each view a request channel with one correlated result; `snapshot.js` reads the host snapshot a render receives.
- Held drafts in an editable table: `record_edits` with `cancelControl`, and the Zone choice cells in `features/zones/zone_cells.js`, put a small clear-glyph Cancel inside the cell's right edge (`.phc-cell-cancel` in `base.css`), so the row never grows; the reason stays in the cell's anchored error bubble. A refused choice that wrote nothing shows the Model's value again instead of holding the draft. A row marker that will not fit as a word (`table.js` marker `icon`) is an alert glyph with its reason as tooltip and accessible label.
- `overlay.js` with `overlay.css` (bubbles, action menus, notices, dialogs) and `base.css` (the interaction tokens on `:root` and the shared subtabs nav). Pass `tone` to `notice.show`: omitted means `info` (white), `success` is white with a check and fades after `SUCCESS_MS` (3 s, held on hover or focus), `warning` is yellow, `error` is red; `data-tone` carries it to CSS. Host notices for a completed context-menu command use `:success`. Toolbar glyphs are Lucide outlines with the ISC notice kept beside them; take new glyphs from the same set. Classify each notice as transient or persistent: confirmations and ordinary information may fade on the next meaningful interaction; warnings, errors, and active-tool instructions remain until resolved or explicitly dismissed.
- One row of chrome above an inventory (`view_controls.js`, `inventory_grid.js`): the filter field, Group by, Order by, a sort-direction icon toggle, a muted count ("2 total", "1 of 2"; a screen may word it, as Zones / Faces does with "2 Zones · 1 filter"), a help button holding the keyboard hint, then the fill tools, which appear once a range of cells is selected and keep their place while idle so nothing moves. A tab's settings end the row. A screen that opts into column sorting (`columnSort: true`) hides Order by and the direction toggle and sorts and filters from each column's menu instead (`column_menu.js`: Sort A to Z, Sort Z to A, a "Show" value checklist with Clear filter; a filtered column's ellipsis becomes a filter glyph that stays at rest). No row-number column: a row's position changes with sorting and filtering, so it is not a reference.
- A tree row with nothing under it keeps the chevron's place but offers nothing to open: give the table `expandable(row)`. A value a row still needs is flagged on its own cell: the enum pill turns amber, reads "?", and its accessible name says what to set ("Set Wall 2 boundary"). There is no separate State column: anything else the row needs (a stale adjacency, a missing Attached zone record) is flagged amber on the cell where it is fixed, with the reason in its tooltip.
- An enum cell is `select.phc-enum-cell` (`table.css`): a compact 24px pill with a chevron on every screen, neutral unless the value has a colour of its own through `--category-fill`. A value that cannot be chosen there (a paired Surface) is the same pill read only, `span.phc-enum-pill`, with what sets it in its tooltip. Face types and boundary conditions take a light tint of honeybee's display hue, the one the viewport's Colour-by modes draw: `face_words.fill(field, value)` or a `fill` on a `selectFields` choice, never a feature-local palette. Never style a select by its column name.
- A cell under a header that names a unit holds the number alone: `units.format(..., { showUnit: false })`.
- `table.js` and `table.css`: shared table behavior. A quiet grid: a hairline under each row and column separators only in the header. Hover washes the whole row over whatever each cell shows; it never tints one cell or borrows a chip's colour. `tree: true` makes top-level rows group headings (tinted, bold, a firmer rule above). Disclosure chevrons are borderless glyphs, named "Collapse Zone 1" rather than repeating the row's kind. Header-edge separators provide mouse and keyboard column resizing; double-click resets a width. Show/hide choices go in a Table options action menu in the control row (Zones / Faces: the Ground depth column, and Colour by for a mode no visible column offers), never in-flow controls. A column declares header actions (`headerActions(field)`): nodes the caller builds, shown on header hover or focus, with a pressed or filtered one kept at rest. A row checkbox (`check`) heads the Actions cell with a header box beside "Actions"; `revealRowActions` keeps row icons and unchecked boxes quiet until the row is hovered or focused, and while any row is checked every box shows. Use the shared cell-input and editable-cell classes so the table grid supplies the resting boundary and the cell supplies interaction emphasis. Focus styles and resized widths must preserve sticky offsets and never move identity cells unexpectedly.
- `overlay.js` `formDialog(className, onCancel)` and the form-dialog class in `overlay.css`: the one modal. Its top-right close (`.phc-dialog-close`) calls `onCancel`, like Escape, and is put back on every open; closing returns focus to the opener. `record_form.js` is the lifecycle every record form shares: container, title, submit and Cancel order, status line, one single-flight request. `ui.table` passes the clicked row button as the third `action` argument so a bubble can anchor to the row that asked.
- Stylesheets, one owner each, linked in this order by `index.html`: `base.css` (tokens, page defaults, typography, shared controls and navigation), `overlay.css`, `shell.css` (the shell, the Export section and the status bar), `table.css`, `features/zones/zones.css` (the Zones / Faces screen, its selection bar contents). The selection bar itself is a kit part styled in `overlay.css`. A screen's override of a shared primitive carries that screen's scope class so specificity, not link order, decides it.
- `unit_field.js` `UnitField`, `units.js`, `unit_preferences.js` and `fields.js`: every unit-bearing input and its stored-field descriptor.

## Accepted screen patterns (local)

- Table column headers with actions (`table.js`, `table.css`): one semantic column header contains two
  visual bands, a 34 px label row and a 28 px action row, separated by a hairline. Every column reserves
  the lower band, including columns without actions. Labels align left on one baseline; narrowing a
  column elides its label, whose tooltip retains the complete text. Palette and menu controls keep
  their existing hover, keyboard-focus and persistent active states. Both bands stick and resize
  together. Tables without `headerActions` keep their compact header. Accepted by Ed on 2026-10-05.

- Zones / Faces: `features/zones/overview.js`, `features/zones/zones.css`, accepted from a mockup on 2026-10-04 (archived packet `zones-table-first`). One table spanning the pane, no inspector. Zone rows carry Name, Building-Segment, Level and Ground depth as cells edited in place (`zone_cells.js`, each commit one Undo step); Face rows carry type and boundary as chips and the Assembly. A Face with no record yet is a row too, under one "N unclassified Faces" summary row per Zone: open by itself at ten or fewer, closed above that, and showing its first fifty with a "Show all" row beyond. Choosing a type or a boundary on such a row classifies it. Column headers hold the Colour-by toggle for that column's mode (Assembly's offers Assembly and Window Type through the `construction` group) and the column menu. Select and Locate are separate: a checkbox per row builds the panel's checked set (a Zone's box checks its Faces and reads mixed, Shift-click checks a range), which a new SketchUp selection replaces; Locate frames and outlines without selecting. Row icons show on hover or focus. While Faces are checked, the selection bar floats over the bottom of the table with "N Faces selected" (", M hidden" under a filter) and Type, Boundary and Assembly, each choice one Undo step for every checked Face, a value they do not share reading "Mixed"; these controls remain available while painting. Escape unwinds an open menu, the Classify tool, the checked set, then Locate's outline.
- Attached-zone inline creation: `features/zones/attached_zone_assignment.js` and `features/zones/attached_zone_fields.js`. A `formDialog` opened from a Face's boundary chip; Cancel leaves the chip unchanged, a refusal keeps the draft, success closes and restores focus to the chip.
- Zones / Faces creation stays in SketchUp's native context menu. The panel header has no Make Zone
  button or unavailable-reason icon; its remaining tools and settings stay at the upper right.
  Accepted by Ed on 2026-10-05. A SketchUp toolbar alternative remains a future decision.
- A blocked action can carry `ui.reasonButton(action, reason)` beside it: an alert icon named "Why <action> is unavailable" that opens the reason in an anchored bubble.
- Checked-Zone Solve (`features/zones/overview.js`): the selection bar reports fully checked Zone occurrences and offers Solve for that explicit set once at least two qualify. Mixed Zones are excluded; fully checked hidden Zones remain in scope. The solver refuses a reciprocal write to an unchecked neighbour and names it for retry. Painting leaves this bar available. No permanent whole-Model Solve button. Accepted by Ed on 2026-10-05.
- Column-scoped Face painting: `features/zones/classify.js` contributes paint icons beside values in the Type, Boundary and Assembly column menus. The checkbox/name is the visibility control; the sibling paint icon starts a reset field intent and closes the menu. Include all declared choices and local Assemblies even when unused. Surface, Attached zone and Assembly None have no direct paint icon; the Boundary menu has an inline Attached zone select and New route. There is no separate paint picker. An active intent has a persistent pressed header paint glyph, whose tooltip names the value; clicking it stops the whole tool. External multifield intents show each active column. A concrete paint choice shows its matching Colour-by mode while the tool runs (Attached zone uses Boundary), without remembering it; stopping puts back the mode from before, unless the user picked a mode meanwhile, which stays (`ColourBy::Lease`, decided by Ed on 2026-10-21, #170). Bare native tool activation shows the remembered mode, or Face type, the same way. Escape closes menu/dialog before stopping the native tool. Attached zone carries its boundary/reference together and retains Save/Cancel, refusal, focus and model-switch protection. Checked-Face and Solve controls remain independent. Accepted and refined by Ed on 2026-10-05.
- Colour-by: `sections/colour_by.js`. A column header's palette toggle (`HeaderToggle`) turns its mode on and releases any other; pressing it again turns Colour by off; a group binding with several modes opens a menu of them. The panel legend strip is removed (accepted 2026-10-05). The active mode's colour key is disclosed as swatches beside its column's Show choices. Column filters combine to narrow the table and mute excluded viewport geometry, including partial Zones; Clear filter restores that column's scope. Text search and collapsed rows remain table-only. The palette and filter glyphs keep active state visible in the header. Modes and rows come from the shared service's legend; a mode no column offers is reached from the screen's Table options.
- Export: `sections/export.js`. A running export locks tab changes through the navigation guard and keeps its progress and Cancel visible.
- Assembly Builder: `features/assemblies/editor.js`, `features/assemblies/canvas.js`, `features/assemblies/stage.js`, `features/assemblies/assembly.css`. Use for compact toolbars, header metrics, contextual inspectors, crisp drawings, insertion controls, and anchored editors. One edge insert control for the whole drawing moves to the edge the pointer is near (layers on top and bottom edges, Layer-Segments on side edges), is named by its result ("Insert layer above"), refuses on a membrane's side edges with the reason, inserts at a round unit-aware default and selects what it made; it hides while a Material is dragged. Thickness and width use the shared light rules and boundary dots; clicking a value swaps it for an inline UnitField with its unit beside it. Enter or leaving applies; one Escape restores and closes while preserving selection. Invalid or refused edits stay visible, and drafts survive repaint. Enter returns focus to the value after acceptance; blur keeps focus on the next control. The width line spans exactly the selected Layer-Segment. A second click on the selected Layer-Segment lets it go. The type and exterior hints are the tinted pills, and the exterior film note names the exterior condition. Hover never opens a dimension input. Layer tools holds the air-barrier choices and ends with Delete Layer; a membrane's label selects its Layer for those tools without offering numeric thickness. The Layer-Segment properties bubble lists its Material's conductivity, density, specific heat and emissivity read only. An info icon beside the metrics explains the U-value: the films used, both results, and any warnings or findings. `Bubble.openedWithFocus` tells an owner's `onOpen` a deliberate open from a hover or a repaint's reopen.
- Assembly Builder toolbar (`features/assemblies/inspector.js`, `assembly.css`): centered on the
  drawing work surface with a white background, rounded border and subtle shadow. Selection and
  Material context comes first, then divided view and Assembly action groups using shared icon
  buttons and tooltips. Add Layers through drawing edges or the contextual Layer menu, without a
  duplicate toolbar Add Layer button. Keep Material Library available without a selection. At narrow widths,
  reserve the selection row's height so selecting a Layer-Segment does not move the drawing.
  Insert Layer-Segments through their drawing side edges; omit the duplicate toolbar insert icon.
- Assembly cross-section (`features/assemblies/stage.js`, `assembly.css`): center geometry itself
  with balanced dimension gutters, keeping film labels and width dimensions in the same frame.
  Width edits grow from the center while the drawing fits and retain zoom; larger drawings scroll
  with both ends reachable. A drawing hit target uses the rendered height, without a standard
  button minimum height that would overlap a thin neighbouring Layer or dimension control.
- Assembly insertion hover (`features/assemblies/stage.js`, `assembly.css`): the active edge line
  and plus control are one hover state. Moving over the button's SVG or paths retains that edge;
  decorative strokes never receive pointer events. Edge hover replaces the center's full-segment
  wash, and repeated moves on the same edge do not reset its state. Top and bottom cues span the
  Layer with a stable midpoint; side cues span the Layer-Segment. Preserve selection and drop/focus
  feedback separately, and clear the edge on exit or a busy/draft/Material-drag guard. Reset the
  generic button outline on drawing hit targets, so an unselected neighbor near an insertion edge
  cannot inherit a teal hover border; only explicit drawing states provide their outlines.
- Assembly selection (`features/assemblies/assembly.css`): a light, pointer-transparent teal hatch
  descends from upper left to lower right, crossing the unassigned hatch while preserving the
  Material fill. Center the 2 px feedback outline over the SVG's 1 px base stroke (`outline-offset: -1px`),
  covering it on both sides so shared and exterior edges read evenly. Keep the selection perimeter teal at
  rest; center hover/focus uses the red drawing perimeter, and active insertion edges suppress
  the selected perimeter while retaining the hatch. Drawing hit targets must override the shared
  pressed-button fill through hover and focus so they never obscure the Material. Stack selected
  hit targets above their neighbors, with the pointer-transparent insertion edge and plus above
  selection, so later segments cannot overpaint a shared selected boundary.
- Library and library sidebar: `library/section.js`, `library/sidebar.js`, `library/library.css`. Use for browsing density, source status, filters, row selection, and collapsible sidebar behavior. The sidebar is provider-agnostic: it shows a provider's name and connection state, never its address.
- Assembly contextual Layer tools (`features/assemblies/layer_tools.js`, `stage.js`, `assembly.css`):
  reveal a gear beside the thickness on Layer hover or keyboard focus and keep it visible while its
  menu is open. Reserve gutter space so the value and drawing stay stationary; preserve hover while
  crossing to a protruding icon beside a thin Layer. Hide the gear while an inline thickness field
  owns that space. The gear targets its explicit Layer without changing Layer-Segment selection.
  The drawing gear is the sole Layer tools entry point; keep the toolbar focused on segment actions.
  Mount the feature-owned menu outside the scrollport, retain stable Layer identity
  across repaint/reordering, and return focus on Escape.
- Assembly Layer drag (`features/assemblies/layer_drag.js`, `stage.js`, `assembly.css`): a six-dot
  grip sits beside the gear and shares its reveal and its hiding under an inline thickness field.
  Past a 6 px threshold a small ghost follows the pointer and a red `--drawing-highlight` line marks
  the nearest Layer boundary, muted on the Layer's own place; the drawing and selection stay still
  and no Layer-Segment takes a hover outline. Boundaries come from layout millimetres and the zoom,
  so thin Layers are as reachable as thick ones. One changed drop sends one atomic action and one
  Undo step; Escape, blur, a lost release, a release outside the frame, a repaint and disposal send
  nothing, and a press over a draft or request refuses with its notice without taking focus. The
  grip has no tab stop; Move outward and Move inward in the gear's menu are the keyboard route. A
  grip ships only with its working gesture and Model operation; never show an inert one.
- Assembly thickness applicability: if a Material category snapshot makes a Layer a membrane during
  an unfinished thickness edit, retain the draft visibly with a reason and require Escape to cancel.
  Keep Enter/blur writes and navigation blocked. A clean membrane has no numeric editor; cancellation
  returns focus to its membrane label. Restoring the original category must not silently accept the draft.
- Library tabs: `library/section.js` and `features/windows/inventory.js`. One page heading for every tab, holding the active tab's "+ New" beside Export library; each tab body opens with the shared action bar (view controls, then tab settings) and keeps it to one line at 1280 px. Tab settings sit at the end of the action bar through the kit `Inventory`'s `settings` option, as compact controls that open a choice list (the current choice `aria-pressed`) or a single-value bubble; the Psi-Install Types Model defaults are the example. Record forms use `formDialog`; a record's uses open in a bubble anchored to its row action.
- Thermal Bridges: `features/thermal_bridges/`, accepted by Ed on 2026-10-26 after five changes from his host review. One page header over Types and Schedule subtabs. Types is the kit `Inventory` with column menus (`columnMenus`), under an always-present assign bar: the native selection's Edge count, a type, a quantity, Assign and Clear, the reason on a disabled Assign through `ui.reasonButton`, and a success notice naming the type and the number of Edges on each write (the right-click menu confirms the same way). Used length comes from the one schedule read and shows a dash once the Model has changed. Schedule reads on request (opening, choosing a subtab, Refresh) with Refresh before a short "Changed since read"; a row click or its icon Locates, and a Locate it sent keeps the read current; findings sit behind an alert glyph in a bubble mounted outside the table (`detachedTrigger`), so its scroller and sticky cells never clip it; totals by type take the full row with totals by group beneath; Edges in no run collect under "Not in the schedule".
- Arming a viewport tool from a bar (`features/thermal_bridges/edge_tool.js`, `assign_bar.js`, `thermal_bridges.css`), accepted by Ed on 2026-10-26 with the P3b-07 edge tool. The assign bar's "Assign by clicking" arms the tool with the bar's own type and quantity and stays pressed at rest, not only on hover or focus, while the tool has the viewport; a second click stops it, and Stop sits beside it while it runs. Changing the bar's type or quantity re-arms a running tool. The tool's explicit-reference equivalent is the bar's own action (`edges.assign`). Use this for any bar whose values a viewport tool applies by clicking.
- Window Types: `features/windows/editor.js`, `features/windows/canvas.js`, `features/windows/windows.css`. Use for the page-header action hierarchy, title and metrics, floating notices, contextual drawing tools, selection treatment, edge inserts, single-value dimension bubbles and the adapted collapsible sidebar. Its drawing toolbar groups by job, each group one outline: View (viewing side, zoom, fit), Window Type (flip, eyedropper, Undo help), Assign (the library's product kind and, for frames, the side), and the selected elements' edits at the right while something is selected. Choices between named states in a toolbar are `select.phc-choice-pill`.

## Shared visual semantics

- `--interaction-highlight`: interactive borders, selected controls, active sidebar rows and selected drawing elements.
- `--interaction-highlight-hover`: stronger hover and active emphasis.
- `--interaction-highlight-tint`: low-contrast selected backgrounds, including the selected drawing element fill.
- `--drawing-highlight`: drawing hover, keyboard focus, insertion geometry and drop targets; never selection.
- `--drawing-highlight-halo`: focused or hovered drawing affordance halo.
- `--line`, `--muted`, `--surface`: neutral structure and hierarchy.

Do not create a feature-local substitute for these semantics without evidence that the shared token is wrong app-wide.
